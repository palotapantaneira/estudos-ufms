# Estudos UFMS R5 — 25/11/2026

Base: UFMS_Estudos_Revisao_Didatica_PWA(2).zip (R4). Versão 2026.11.25-r5. A data da primeira sessão do cronograma continua 24/11/2026. Não houve nova retificação de edital conferida nesta atualização; foram mantidas as referências e a programação da R4.

## Como atualizar pelo GitHub Pages (recomendado)

1. Termine as questões em andamento na R4. Em Configurações → Atualização manual, toque em **Preparar atualização · baixar backup**. Guarde o JSON na pasta Downloads e confira que foi salvo. Se usa mais de um dispositivo, faça backup em cada um. Não envie o JSON para o GitHub.
2. Baixe e extraia `UFMS_Estudos_R5_PWA.zip`. Abra a pasta `UFMS_Estudos` extraída.
3. Abra o **mesmo repositório e a mesma pasta de publicação** no GitHub. Use Add file → Upload files. Envie os arquivos de dentro da pasta `UFMS_Estudos`, substituindo os arquivos existentes com os mesmos nomes e acrescentando `r5_content.js` e `qr_local.js`. Não coloque uma pasta adicional no caminho publicado se anteriormente o `index.html` estava na raiz.
4. Confirme em Commit changes. Aguarde o GitHub Pages concluir o deploy. Abra o aplicativo online, feche-o completamente e reabra quando a atividade atual estiver concluída; o service worker atualiza o cache. Em Configurações, confirme o identificador `2026.11.25-r5`.
5. Confira os módulos concluídos, as respostas, o caderno de erros e as anotações. O armazenamento local `ufms_study_v1` foi mantido. Se os dados não aparecerem, restaure o backup R4 pelo botão **Restaurar backup**. Não limpe os dados do site nem desinstale antes de conferir a migração.

O GitHub Pages serve os arquivos do aplicativo; não armazena o progresso de estudo. Manter o endereço/origem e usar o mesmo navegador/perfil preserva o armazenamento local, em condições normais. A restauração JSON permite combinar dados de dispositivos diferentes. O backup não contém os arquivos PDF originais armazenados em IndexedDB, nem uma tentativa de quiz/jogo aberta. Guarde os PDFs em separado. Se preferir o HTML avulso, faça o mesmo backup e restaure depois de abrir a nova versão; arquivos locais com nomes/endereços diferentes podem ter armazenamentos distintos.

## Pareamento QR e sincronização automática

1. Nos dois dispositivos, abra a versão R5 publicada em HTTPS no mesmo endereço do GitHub Pages. Conecte ambos à internet e preferencialmente ao mesmo Wi-Fi.
2. No tablet, Configurações → Parear dispositivo → Gerar QR Code. Permita o mecanismo externo de sinalização quando perguntado. O convite tem validade de cinco minutos.
3. No celular, Configurações → Escanear QR Code. Permita câmera e confirme o convite. Também é possível ler o QR com a câmera nativa e abrir o endereço quando ele for um link HTTPS; ou copiar/colar o convite se o leitor de câmera não estiver disponível. Mantenha os dois aplicativos abertos enquanto conectam.
4. Os dispositivos pareados são lembrados no armazenamento local. A conexão tenta se restabelecer e combina os registros automaticamente quando ambos estão abertos, online e conectáveis. Veja a última sincronização e os dispositivos em Configurações. Desvincular não apaga seu estudo.

Esta solução usa a biblioteca PeerJS 1.5.5 carregada do jsDelivr, sinalização pública PeerJS e servidor STUN. A biblioteca jsQR 1.4.0 é carregada se o navegador não oferecer leitor nativo. A geração do QR é local (código MIT de Kazuhiko Arase). O histórico é transmitido pelo canal WebRTC criptografado; o GitHub não recebe o progresso. Não é sincronização em nuvem, nem é garantida entre redes que bloqueiem conexão direta: não foi implantado servidor TURN, conta ou banco remoto. Se um dispositivo estiver fechado, o navegador pode suspender a conexão. Se não conectar, use Transferência offline / Quick Share (JSON) ou a conexão manual legada. Não compartilhe o QR publicamente. Os PDFs originais e o cronômetro ativo ficam locais; os registros de tempo concluído são combinados. Em edições concorrentes, a versão mais recente da anotação ou tentativa de simulado prevalece.
